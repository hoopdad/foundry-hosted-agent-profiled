# Azure SDK API Profiling

The host profiles Azure SDK HTTP calls with a custom [`SansIOHTTPPolicy`](https://learn.microsoft.com/en-us/python/api/azure-core/azure.core.pipeline.policies.sansiohttppolicy?view=azure-python). Its `on_request`, `on_response`, and `on_exception` callbacks assign a correlation ID, record a UTC timestamp, and calculate elapsed milliseconds with a monotonic clock; logs include the HTTP method, response status, and URL path, while query strings and fragments are removed to avoid exposing SAS tokens or other secrets.

The policy is attached to token requests made by [`ManagedIdentityCredential`](https://learn.microsoft.com/en-us/python/api/azure-identity/azure.identity.managedidentitycredential?view=azure-python) and to download/upload requests made by [`BlobClient`](https://learn.microsoft.com/en-us/python/api/azure-storage-blob/azure.storage.blob.blobclient?view=azure-python). Identity receives both legacy and current per-retry option names for SDK-version compatibility, while Blob Storage uses its additional-pipeline-policy hook, so profiling occurs inside the clients' HTTP pipelines without changing the application's request handling or blob-transfer logic.
